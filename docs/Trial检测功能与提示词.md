# Trial 简易检测功能与提示词

更新日期：2026-07-15

> **方案边界备注（2026-07-14）**：YOLO 方案和正式项目管理流程已暂停。本文中对本地 YOLO、算法 Worker、正式项目或审核流程的提及仅用于说明 Trial 的隔离边界；Trial 的 Qwen 视觉模型链路仍是当前有效范围。

本文记录 `/trials/new` 免费试用页面及其 `/api/trial/*` 后端接口的当前实现、接口约束、图像处理流程、结果过滤规则，以及实际发送给视觉模型的完整提示词。默认使用 Qwen，管理员可在“管理中心 -> 推理设置”手动切换到备用的智谱 GLM。提示词的代码源文件是 `backend/app/services/trial_qwen_inference.py`；修改提示词时应同步更新本文和相关自动测试。

## 1. 功能范围

Trial 是独立于正式项目检测任务的快速体验链路。它不调用 `algorithm-model` 中的本地 YOLO 权重，也不经过算法 Worker，而是由 Web 后端直接调用阿里云百炼兼容接口中的 Qwen 视觉模型。

Trial 会先根据上传时提取的照片元数据区分可见光照片和 IronRed 热成像照片，再选择检测范围：

| 系统类型 | 页面名称 | 识别范围 |
| --- | --- | --- |
| `crack` | 裂缝 | 墙面、面砖或构件表面的可见裂缝 |
| `spalling` | 剥落 | 掉块、缺角、破损、材料脱落或基层外露 |
| `hollow` | 空鼓 | 仅在 IronRed 热成像照片中识别成片的黑色低温异常区域 |

普通可见光照片只检测 `crack`、`spalling`，不能输出 `hollow`。热成像照片只检测 `hollow`，不能输出可见光缺陷类型。锈蚀识别暂未开放，不进入 Trial 推理范围。两种照片使用彼此独立的提示词和后端类型白名单，混合上传时按每张照片分别分流。

## 2. 调用链

```text
浏览器 /trials/new
  -> POST /api/trial/photos 上传并暂存图片
  -> POST /api/trial/generate 提交 photo_ids
  -> Web 后端从对象存储读取图片
  -> 根据 thermal_imaging_available 选择可见光或热成像提示词
  -> EXIF 方向修正并转换为 RGB
  -> 按 1280 x 960、25% 重叠切片
  -> 每个切片独立调用 Qwen chat/completions
  -> 校验 JSON、类型、置信度和 bbox
  -> 坐标转换回原图并执行分类别 NMS
  -> 置信度过滤后生成 findings 和 raw_model_outputs
  -> 后端在同一任务内保存 Trial 检测结果
  -> 返回检测结果、archived_report_id 和 archived_report_title
  -> 前端在原图上绘制缺陷框
  -> 存档后可在报告详情查看或导出 Word
```

单个切片请求不携带其他切片或历史对话，避免不同图片和不同区域之间相互干扰。一个 Trial 任务内的所有图片共用并发控制器；管理员可在推理设置中将同时在途请求数配置为 1 到 10。

检测与存档由后端在同一任务内完成，不再依赖 Trial 页面收到推理响应后发起第二次存档请求。因此检测过程中切换菜单、离开 Trial 页面、刷新或关闭浏览器，不会取消已经到达后端的任务；后端完成推理后仍会保存结果。用户可选择“继续检测”并追加照片；下一次生成只提交本轮新上传、尚未存档的照片，已经完成的照片不会再次调用模型。“完成并退出”返回首页，已存档结果仍可在“检测结果”中查看。

## 3. 上传和接口约束

### 3.1 上传图片

`POST /api/trial/photos`

- 需要登录。
- 仅支持 JPG、JPEG、PNG。
- 单张最大 10MB；不限制每位用户每天上传或检测的照片总数。
- 默认每位用户按北京时间每天最多使用 800 次模型 API 请求；按预估切片数在调用前预占，失败时退回，管理员可在推理设置中调整额度。
- 单次生成最多使用 10 张图片。
- 上传后保存原始文件信息、对象存储位置和照片元数据。
- 只有照片同时满足 `XMP-drone-dji-ImageSource=InfraredCamera` 和 `IFD0-ImageDescription=IronRed` 时，才记录 `thermal_imaging_available=true` 并进入“仅空鼓检测”分支；否则进入裂缝、剥落两类可见光检测分支。

### 3.2 生成预览结果

`POST /api/trial/generate`

典型请求：

```json
{
  "report_name": "东立面简易检测结果",
  "models": ["裂缝", "剥落", "空鼓"],
  "photo_ids": ["照片 UUID"]
}
```

当前检测类别由后端按照片类型固定决定，`models` 用于结果描述和存档配置，不直接控制提示词。页面默认提交裂缝、剥落、空鼓三类；每张可见光照片只请求裂缝和剥落，每张热成像照片只请求空鼓。

返回内容包含：

- `findings`：置信度通过业务展示阈值的最终页面结果。
- `raw_model_outputs`：通过基础解析的模型候选框，包含是否进入最终结果的 `visible` 标记、切片信息、跨 TILE 融合参数和 NMS 参数。
- `archived_report_id`、`archived_report_title`：后端已保存结果的 ID 和报告名称。

### 3.3 自动存档结果

`POST /api/trial/results`

当前 Trial 页面不再依赖此接口完成自动存档；`POST /api/trial/generate` 在推理成功后已直接保存结果。该接口暂时保留用于兼容旧客户端。后端存档时执行 `> 0.60` 的置信度过滤，将结果保存到 Trial 检测结果及报告快照 JSON 中。每次“继续检测”后的新批次独立存档，并且只包含该批新上传的照片。Trial 存档不进入正式项目的算法任务和人工审核流程。

## 4. 图像切片与坐标转换

当前固定参数：

| 参数 | 值 |
| --- | --- |
| 切片宽度 | 1280 px |
| 切片高度 | 960 px |
| 相邻切片重叠 | 25% |
| 边缘补白 | 白色 |
| Qwen bbox 坐标空间 | 0 到 999，兼容边缘值 1000 |
| 跨 TILE 融合 IoS 阈值 | 0.60 |
| NMS IoU 阈值 | 0.5 |
| 请求并发 | 管理员可配置 1 到 10，默认 5 |

模型返回 `bbox: [x1, y1, x2, y2]`。后端先按 `x / 1000 * 1280`、`y / 1000 * 960` 转换为切片像素坐标，裁掉落入白色补边的部分，再叠加切片左上角偏移量，得到原图坐标：

```json
{
  "x": 120.0,
  "y": 60.0,
  "width": 80.0,
  "height": 160.0
}
```

坐标转换后，后端先处理相邻重叠 TILE 返回的同类框。当两个框来自不同且实际重叠的 TILE，并且交集占较小框面积的比例（IoS）不低于 `0.60` 时，认为它们是同一缺陷的局部/完整重复结果，使用两个框的外接并集作为融合框，置信度和说明沿用较高置信度结果。

融合完成后再按缺陷类型执行 NMS。因此高度重叠但未达到跨 TILE 融合条件的两个 `crack` 框仍会去重，同一区域的 `crack` 和 `spalling` 则不会互相融合或抑制。

## 5. 结果校验和置信度

后端只保留满足以下条件的模型项：

- 项目是 JSON 对象。
- 可见光分支的 `type` 只能是 `crack`、`spalling`；热成像分支只能是 `hollow`；历史别名 `missing` 会归一化为 `spalling`。
- `confidence` 是 0 到 1 的有限数字。
- `description` 是不超过 20 个字符的字符串。
- `crack` 的说明若表示“正常”或“非缺陷”会被丢弃；若只描述瓷砖缝、分格缝、拼缝、构造缝、板缝或接缝，而没有局部扩宽、宽度不均、破损、错位、分叉离缝或延伸入板等异常证据，也会被丢弃。
- `bbox` 恰好包含四个有效坐标，且范围和顺序合法。
- 坐标映射后与图片有效区域存在正面积交集。
- `crack` 在 `1280 × 960` 模型输入切片中的 bbox 长边必须达到 `64 px`；该规则只过滤短小框，宽度很窄但长度足够的裂缝仍会保留。

当前存在两级置信度控制：

| 阶段 | 条件 | 作用 |
| --- | --- | --- |
| 可见光提示词 | `confidence >= 0.50` | 要求模型不输出低于 0.50 的裂缝或剥落候选，减少无效输出 |
| 热成像提示词和后端基础解析 | `confidence >= 0.40` | 热成像提示词仍使用 0.40；后端统一丢弃低于 0.40 的异常返回 |
| 页面展示和存档 | `confidence > 0.60` | 只有高于 0.60 的结果进入 `findings`、页面标注和存档 |

所以置信度正好等于 `0.60` 的候选可能出现在 `raw_model_outputs` 中，但不会显示或存档。

## 6. 当前完整提示词

### 6.1 可见光照片提示词

以下内容与 `TRIAL_QWEN_PROMPT` 保持一致：

```text
你是建筑外墙缺陷检测助手。
当前输入是一张建筑外墙的局部切片图片，不是完整建筑立面。请只判断该切片中是否存在以下外墙缺陷：
 - crack：墙面、涂层、抹灰层或面砖表面的异常细窄线状裂口；正常瓷砖缝、分格缝、拼缝和构造缝不属于裂缝
 - spalling：外墙瓷砖/面砖、涂层或抹灰层已经发生块状、面状的实体材料脱落缺失
判定顺序必须是：先排除正常构造线，再在剩余候选中识别 crack 或 spalling。不要因为线条细长、颜色较深就直接判定为 crack。
规则：
1. 只输出 JSON 数组，不要输出解释、Markdown、标题或其他文字。
2. 如果没有发现明显缺陷，输出 []。
3. 每个结果必须包含以下字段：
 - type：只能是 crack 或 spalling
 - confidence：0 到 1 的小数
 - bbox：格式为 [x1, y1, x2, y2]
 - description：不超过20字
4. bbox 使用 Qwen3-VL 原生归一化坐标，原点在左上角；每个坐标必须是 0 到 999 的数字，不是像素值。
5. 正常构造线排除具有最高优先级。候选线若与面砖或墙板边界重合，并且整体笔直等宽、边缘完整、没有局部破损/扩宽/错位，或与相邻线等间距重复并组成规则横竖网格，应判定为正常瓷砖缝、分格缝、拼缝或构造缝，禁止输出。即使线条颜色很深也不得输出。
6. 完整、规则、边缘无破损的窗框边缘、装饰线条、伸缩缝、墙体阴阳角和规则板块边界都不是 crack；但其邻近或上覆的异常裂口仍须按规则7至10判断，不能仅因靠近窗框或构件边界而排除。局部切片上下文不足、无法区分裂口和正常接缝时，宁可输出 []。
7. crack 必须具有区别于正常构造缝的异常形态证据，例如不规则走向、宽度明显变化、锯齿破损边缘、分叉、错位，或裂口横跨/延伸进入面砖或墙板表面。仅有笔直细线、普通暗线或“接缝处细纹”不足以判定为 crack。
8. 位于正常接缝上的异常只有在可见局部扩宽、宽度不均、边缘破损、错位、分叉离开接缝或延伸进入板面时，才可输出 crack；description 必须描述该异常证据，不能只写“分格缝”“拼缝裂纹”或“接缝细纹”。
9. 当候选与窗框下沿、面砖缝或板缝邻近或部分重合，但裂口本身连续可见，并有宽度不均、锯齿/破损边缘、局部扩宽、错位、偏离接缝或延伸进入板面等异常证据时，不得仅因其走向较直、靠近构件边界或沿接缝延伸就排除；应输出 crack。
10. 对同一条连续裂缝，bbox 必须覆盖从可确认起点到终点的完整可见长度，包括较细但仍连续的中间段；不得只框最宽、最明显或破损最重的一小段。裂缝不可见的正常接缝不得纳入 bbox。
11. spalling 必须同时具有面状或块状缺损形态，以及至少一种实体材料损失证据：不规则破碎边缘、可见断面或厚度、凹陷阴影、水泥/砂浆基层外露。不得仅根据颜色较深、颜色较浅、纹理变化或模型自己的语义猜测“露出基层”。修补带、补漆或腻子痕迹、矩形色差区域、旧新涂层交界都不是 spalling。
12. 同一候选区域先在 crack 和 spalling 中二选一，不要重复输出两类。完整表面上的污渍、阴影、反光和普通划痕都不是缺陷。
13. 只有当缺陷较明显时才输出；不确定时请降低 confidence，低于 0.50 的目标不要输出。被规则5至6排除的正常构造线无论 confidence 多高都不得输出。
14. 返回前逐项自检：若 description 表示“正常”“非缺陷”，或只表示瓷砖缝、分格缝、拼缝、构造缝、板缝、接缝而没有规则7至9要求的异常证据，必须删除该项。
以下反例都必须输出 []：
 - 三条等间距、等宽、笔直的竖线，与墙板边界重合
 - 一条边缘完整、等宽、无破损的连续横线沿多块面砖或墙板边界延伸
以下正例应输出 crack：
 - 窗框下方一条连续横向裂口，虽邻近窗框或板缝，但可见破损边缘和宽窄变化；bbox 覆盖整条连续可见裂口
输出示例：
[
  {
    "type": "crack",
    "confidence": 0.82,
    "bbox": [120, 80, 360, 130],
    "description": "不规则裂口横跨面砖"
  },
  {
    "type": "spalling",
    "confidence": 0.76,
    "bbox": [420, 210, 560, 360],
    "description": "面砖掉块并露出砂浆"
  }
]
```

```text
    "bbox": [120, 80, 360, 130],
    "description": "不规则裂口横跨面砖"
  }
]
```

### 6.3 热成像照片提示词

以下内容与 `TRIAL_QWEN_THERMAL_PROMPT` 保持一致：

```text
你是建筑外墙热成像空鼓检测助手。
当前输入是一张采用 IronRed（铁红）色板的建筑外墙热成像局部切片，不是完整建筑立面。该图片只用于识别空鼓，不检测裂缝、剥落、锈蚀或其他缺陷。
请只判断墙面区域中是否存在以下热异常：
 - hollow：疑似空鼓
判定特征：
 - 目标主体是一块连续、成片且尺寸明显的黑色或近黑色低温区域；
 - 黑色区域的多侧被范围同样明显、颜色相对均匀的紫红色墙面背景包围；
 - 黑色区域与周围紫红色之间存在较清楚的热对比边界，形状可以不规则。
规则：
1. 只输出 JSON 数组，不要输出解释、Markdown、标题或其他文字。
2. 如果没有发现明显的疑似空鼓，输出 []。
3. 每个结果必须包含以下字段：
 - type：只能是 hollow
 - confidence：0 到 1 的小数
 - bbox：格式为 [x1, y1, x2, y2]
 - description：不超过20字
4. bbox 使用 Qwen3-VL 原生归一化坐标，原点在左上角；每个坐标必须是 0 到 999 的数字，不是像素值。
5. bbox 只框住成片的黑色或近黑色热异常主体，不要把大面积紫红色背景一起框入。
6. 很小的黑点、零散噪点、孤立像素、细小斑点不是空鼓；黑色候选区域和包围它的均匀紫红色背景都必须具有明显面积。
7. 可识别的窗户、门洞、通风口、设备、屋檐、墙体边缘、伸缩缝、横竖线条及其低温轮廓不是空鼓。
8. 大面积纯黑边框、贴近图片边缘且无法确认被紫红色墙面包围的区域，以及细长的水平或垂直暗带，不要输出 hollow。
9. 不要输出 crack、spalling、corrosion 或其他类型，即使图片中看起来存在这些缺陷。
10. 只有当上述热异常特征较明显时才输出；不确定时请降低 confidence，低于 0.40 的目标不要输出。
输出示例：
[
  {
    "type": "hollow",
    "confidence": 0.86,
    "bbox": [430, 180, 560, 290],
    "description": "疑似墙面空鼓"
  }
]
```

## 7. 视觉模型请求配置

后端读取以下环境变量：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DASHSCOPE_API_KEY` | 空 | 阿里云 Qwen API Key；仅保存在后端，不得使用 `VITE_` 前缀 |
| `QWEN_API_BASE_URL` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 兼容接口基础地址 |
| `QWEN_MODEL` | `qwen3-vl-plus` | Trial 使用的视觉模型 |
| `QWEN3_VL_FLASH_MODEL` | `qwen3-vl-flash` | 阿里云 Qwen3-VL-Flash 模型名 |
| `LOCAL_QWEN_API_BASE_URL` | 空 | 本地 OpenAI 兼容服务地址，例如 `http://127.0.0.1:9005/v1` |
| `LOCAL_QWEN_MODEL` | 空 | 本地服务暴露的模型名，例如 `qwen3-vl-32b` |
| `LOCAL_QWEN_API_KEY` | 空 | 本地服务启用鉴权时填写；未启用鉴权可留空 |
| `LOCAL_QWEN_CONTROL_ENABLED` | `false` | 是否随推理选项自动启动、停止本地 vLLM |
| `LOCAL_QWEN_VLLM_EXECUTABLE` | `vllm` | vLLM 可执行文件路径 |
| `LOCAL_QWEN_MODEL_PATH` | 空 | 本地模型目录 |
| `LOCAL_QWEN_CUDA_VISIBLE_DEVICES` | 空 | 本地模型使用的 GPU 编号，例如 `0,1` |
| `LOCAL_QWEN_CUDA_HOME` | 空 | CUDA 工具链目录；FlashInfer 运行时编译找不到 `nvcc` 时必须配置 |
| `LOCAL_QWEN_USE_DEEP_GEMM` | `false` | 是否启用 DeepGEMM；需要与 CUDA 头文件完全匹配的 `nvcc` |
| `LOCAL_QWEN_USE_FLASHINFER_SAMPLER` | `false` | 是否启用 FlashInfer 采样器；关闭时使用无需运行时 JIT 的采样路径 |
| `LOCAL_QWEN_TENSOR_PARALLEL_SIZE` | `1` | vLLM 张量并行 GPU 数 |
| `LOCAL_QWEN_MAX_CONCURRENCY` | `1` | 本地模型同时处理的最大图像请求数；同时限制后端请求扇出和 vLLM `--max-num-seqs`，32B 模型建议从 1 开始 |
| `ZHIPU_API_KEY` | 空 | 智谱备用 API Key，仅后端读取 |
| `ZHIPU_API_BASE_URL` | `https://open.bigmodel.cn/api/paas/v4` | 智谱兼容接口基础地址 |
| `ZHIPU_MODEL` | `glm-4.6v` | 智谱视觉模型 |
| `TRIAL_REQUEST_TIMEOUT_SECONDS` | `300` | 所有提供商共用的默认单请求超时秒数，不包含本地切片排队时间 |
| `TRIAL_REQUEST_CONCURRENCY` | `5` | 所有提供商共用的默认单任务请求并发数，范围 1 到 10 |

管理员在“管理中心 -> 推理设置”选择阿里云 Qwen、本地 Qwen 或智谱，并在任务调度模块统一维护并发数、每日模型请求额度和每账号检测次数；上传上限、限流窗口、请求超时与任务占位超时继续由后端环境配置维护。所有提供商共用这组调度参数，但本地模型的实际请求并发取页面设置与 `LOCAL_QWEN_MAX_CONCURRENCY` 的较小值，并由 vLLM 在服务端再次限制活动序列数，防止视觉编码批处理触发 CUDA OOM。页面还可维护可见光/热成像提示词。配置保存在 `system_setting` 表中，对下一次新任务动态生效，运行中的任务不变，默认仍为阿里云 Qwen3-VL-Plus。

启用本地模型自动控制后，保存本地模型选项会启动 vLLM，切换到任一云端选项会立即停止 vLLM，因此应在本地检测任务结束后再切换。两个后端 worker 通过进程锁和 PID 校验共享同一个本地模型进程；后端启动时也会按数据库中的选项自动同步。模型加载期间设置页显示“正在启动”，健康检查通过后显示“运行中”。

API Key、API 地址和模型只从服务端环境变量读取，不通过管理接口展示或修改。

每个 Qwen 切片请求使用：

- `POST {QWEN_API_BASE_URL}/chat/completions`；选择本地模型时改用 `LOCAL_QWEN_API_BASE_URL`。
- 一条 `user` 消息。
- 消息内容包含一个 PNG data URL 和按照片类型选定的上述提示词。
- `enable_thinking=false`。
- `stream=false`。

每个智谱切片请求使用：

- `POST {ZHIPU_API_BASE_URL}/chat/completions`
- 一条包含 Base64 PNG 与对应提示词的 `user` 消息。
- `thinking={"type":"enabled"}`。
- `stream=false`。

后端同时读取每次切片响应中的 `usage`，不在本地估算 Token：

- `prompt_tokens`：输入 Token。
- `completion_tokens`：输出 Token。
- `total_tokens`：本次切片请求的总 Token。
- `prompt_tokens_details.image_tokens/text_tokens/cached_tokens`：上游返回时保留图像、文本和缓存输入明细。

每个 TILE 的用量按照片聚合后写入 `raw_model_outputs[].token_usage`，原始 TILE 级明细写入 `raw_model_outputs[].tile_token_usages`。Trial 页和归档后的报告详情在“模型原始输出”弹窗顶部显示任务汇总及每张照片汇总；TILE 明细默认折叠，按需展开。弹窗还显示已返回 `usage` 的请求数和 TILE 请求总数，防止上游缺失统计时把部分数据误当成完整数据。

API Key 缺失、上游超时、HTTP 失败、响应不是合法 JSON 数组，或任一切片请求失败时，本次生成接口返回 503，不降级为模拟检测结果。

## 9. 后续增加缺陷类别的检查清单

不能只修改提示词。新增类别时至少同步检查：

1. 在完整提示词中增加类别定义、正例特征、反例排除规则和输出示例。
2. 在 `DEFECT_TYPE_NAMES` 增加后端解析白名单和中文名称。
3. 在 Trial 接口增加中英文类型映射和默认模型列表。
4. 在前端增加模型名称、检测框类别、中文名称和颜色。
5. 在报告详情和 Word 导出中增加中文标签。
6. 添加单元测试，验证新类型不会被解析器过滤，并能进入接口 `findings`。
7. 使用包含正样本、相似颜色干扰物和无缺陷图片的数据集进行人工验收，记录误检率、漏检率和适合的置信度阈值。

只修改提示词但不修改类型白名单时，模型即使正确返回新类型，也会在后端解析阶段被直接丢弃。
