# 检测时段推荐计算案例

本文用一个真实接口返回的天气案例，说明“检测时段推荐”如何从单日日期、地图坐标、立面朝向和天气数据，计算出当天是否适合红外空鼓检测。

## 1. 先看懂整体原理

这个功能的目标不是“查一个天气，然后直接给一个固定时间段”，而是判断：在用户选定的这一天、这个位置、这个立面朝向下，墙面空鼓区域和正常墙面之间能不能形成足够明显、持续足够久的热红外温差。

可以把它理解成四步：

1. **太阳会不会照到这面墙**：根据日期、经纬度、时区、立面朝向，计算每个时刻太阳在天空中的位置，以及阳光打到墙面上的强弱。
2. **天气会削弱多少热量**：晴天、少云时墙面受热强；中雨、大云量时受热弱。系统用云量、降水把晴空辐照折减。
3. **墙面会怎么升温和降温**：空鼓区背后有空气层，热响应和正常墙面不同。系统用热响应模型预测空鼓区与正常区的温差。
4. **温差是否能稳定检测**：根据温差强度和连续持续时间，将结果分成优选时段、可用时段和不推荐。

### 1.1 为什么不是简单按每小时打分

和风逐小时预报通常是一小时一个点，例如 10:00、11:00、12:00。天气数据是小时级的，但热红外窗口变化可能发生在两个小时之间。如果只按整点判断，容易漏掉 08:40-09:30 这种窗口。

所以当前实现是：

- **天气输入**：来自逐小时或逐日天气预报；
- **内部计算**：按每 10 分钟一个点计算 00:00-24:00；
- **窗口输出**：把连续达标的 10 分钟点合并成时间段。

也就是说，逐小时天气不是最终判断粒度，只是构造当天环境条件的输入。真正的推荐判断粒度是 10 分钟。

### 1.2 为什么当天逐小时数据可能不完整

如果目标日期是今天，而当前时间已经是上午 09:25，天气供应商不会再返回今天 00:00-09:00 的未来逐小时预报。它只会返回当前时刻之后的预报，例如从 10:00 开始。

因此会出现这种情况：

```text
目标日期：2026-07-07
测试时刻：2026-07-07 09:25
逐小时预报：从 2026-07-07 10:00 开始
目标日可用小时：10:00-23:00
目标日缺失小时：00:00-09:00
```

这不是接口错误，而是“今天已经过去的时间不会再作为未来预报返回”。

当前处理规则是：

- 如果目标日逐小时温度点数足够多，就用逐小时温度计算当天平均温度、温度振幅和最高温时刻；
- 如果目标日逐小时温度点数不足，就用逐日预报里的最高温、最低温估算当天温度曲线；
- 如果已有部分逐小时温度，则用已有逐小时最高温出现时间辅助确定 `tempPeakHour`。

### 1.3 选今天和选未来日期有什么不同

日期选择器始终是单选一天，不存在多天范围计算。

区别只在于数据覆盖：

| 用户选择 | 天气数据特点 | 推荐窗口范围 |
| --- | --- | --- |
| 今天 | 逐小时预报只覆盖当前时刻之后 | 只推荐当前时刻之后的窗口 |
| 未来 1-6 天 | 可能通过 72h 或 168h 逐小时预报覆盖 | 只计算所选日期 00:00-24:00 |
| 更远未来日期 | 可能只有逐日预报，没有逐小时预报 | 用最高/最低温估算，只计算所选日期 |

即使调用了 72h 或 168h 接口，也不是计算多天范围。系统会先过滤出用户选择的那一天，只计算这一天。

### 1.4 什么是“正温差”和“负温差”

模型计算的是：

```text
ΔTlocal = Tvoid - Tref
```

其中：

- `Tvoid` 是空鼓区预测温度；
- `Tref` 是正常参考墙面预测温度。

结果解释：

| 温差 | 含义 | 用途 |
| --- | --- | --- |
| `ΔTlocal > 0` | 空鼓区比正常墙面更热 | 正温差检测窗口 |
| `ΔTlocal < 0` | 空鼓区比正常墙面更冷 | 负温差复核窗口 |

正温差和负温差都可能有价值。上午受热阶段常见正异常，降温阶段可能出现负异常。

### 1.5 为什么要看“连续持续时间”

无人机外墙采集不是瞬间完成的。即使某一分钟温差刚好超过阈值，也不一定能稳定完成航线采集。

所以系统同时考虑温差和持续时间，并采用三级结果：

| 结果等级 | 默认规则 | 使用建议 |
| --- | --- | --- |
| 优选时段 | `|ΔTlocal| >= 1.2 ℃`，连续至少 1 小时 | 优先安排采集 |
| 可用时段 | `|ΔTlocal| >= 0.8 ℃`，连续至少 30 分钟 | 可用于短航线、复测或补采，作业前需现场复核 |
| 不推荐 | 未满足以上任一规则 | 建议改选日期或立面朝向 |

### 1.6 这套模型的主要输入

| 输入 | 来自哪里 | 作用 |
| --- | --- | --- |
| 日期 | 用户选择 | 决定太阳轨迹和目标天气日期 |
| 经纬度 | 地图点选 | 决定太阳位置和天气查询位置 |
| 立面朝向 | 用户选择 | 决定太阳是否照到该墙面 |
| 逐小时天气 | 和风天气 API | 提供温度、湿度、云量、降水、风速 |
| 逐日天气 | 和风天气 API | 补充最高温、最低温、云量、降水等 |
| 墙体参数 | 默认标定值 | 预测空鼓区和正常墙面的热响应差异 |
| 阈值和最小时长 | 默认规则 | 判断是否形成有效检测窗口 |

### 1.7 当前模型的边界

这套计算能用于推荐时段，但不是现场检测质量的唯一决定因素。下面因素当前没有精确建模，后续可以继续增强：

- 建筑周边遮挡，例如相邻楼宇、树木、脚手架阴影；
- 真实墙面材质差异，例如涂料、石材、玻璃幕墙和瓷砖的热参数不同；
- 墙面污染、水渍、设备箱等局部干扰；
- 无人机禁飞、风场湍流和现场安全管控；
- 更精确的实测太阳辐射或和风太阳辐射接口。

因此结果应理解为“热红外温差条件推荐”，不是完整施工调度审批。

## 4. 天气参数换算

### 4.1 日平均温度 `tmean`

当天逐小时数据不完整，因此用逐日最高温和最低温估算：

```text
tmean = (tempMax + tempMin) / 2
      = (31 + 25) / 2
      = 28 ℃
```

含义：后续热响应模型需要一个全天环境温度基准值，`tmean` 就是这个基准。

### 4.2 环境温度日振幅 `tempAmplitude`

```text
tempAmplitude = (tempMax - tempMin) / 2
              = (31 - 25) / 2
              = 3 K
```

含义：温度日振幅描述当天温度围绕平均值上下波动的幅度。

### 4.3 温度峰值时刻 `tempPeakHour`

目标日可用逐小时预报中，最高温 31 ℃ 出现在 17:00，因此：

```text
tempPeakHour = 17
```

含义：模型用余弦曲线近似当天环境温度变化，峰值时刻决定最高温出现在几点。

### 4.4 相对湿度 `rh`

目标日可用逐小时湿度平均值为：

```text
rh = 82.36%
```

含义：湿度会影响晴空辐照模型中的可降水量估算，进而影响太阳辐照。

### 4.5 云量和降水折减 `radiationScale`

目标日可用逐小时平均云量为 `80.29%`，逐小时降水合计为 `10.51 mm`。当前实现用一个保守折减系数修正晴空辐照：

```text
radiationScale = clamp(1 - cloud * 0.0065 - min(precip, 10) * 0.03, 0.25, 1)
               = clamp(1 - 80.29 * 0.0065 - 10 * 0.03, 0.25, 1)
               = 0.25
```

含义：HTML 原始算法是晴空模型。实际天气有中雨、高云量时，墙面获得的有效辐照会明显降低，所以用 `radiationScale` 把晴空辐照压低。最低限制为 0.25，避免极端天气把辐照折减到完全不可计算。

### 4.6 对流换热系数 `h`

目标日可用逐小时平均风速为 `8.5 km/h`。先换算为 m/s：

```text
wind_mps = 8.5 / 3.6 = 2.36 m/s
```

再估算对流换热系数：

```text
h = clamp(5 + wind_mps * 2.2, 1, 17)
  = clamp(5 + 2.36 * 2.2, 1, 17)
  = 10.19 W/m²/K
```

含义：风速越高，墙面热量越容易被空气带走，空鼓和参考区的温差更难积累。

## 5. 太阳位置和墙面辐照

目标日期 `2026-07-07` 是当年第 188 天。系统按每 10 分钟一个点，计算 00:00 到 24:00 的太阳位置：

1. 用日期计算太阳赤纬和时差。
2. 用经纬度、时区和时刻计算太阳时。
3. 得到太阳高度角和太阳方位角。
4. 根据东向墙面法线，计算太阳入射到墙面的夹角。
5. 计算水平晴空总辐照 `GHI` 和墙面有效辐照 `Gwall`。
6. 用 `radiationScale = 0.25` 折减晴空墙面辐照。

本案例计算得到：

```text
墙面有效辐照峰值 = 159.72 W/m²
峰值时刻 = 08:50
```

解释：东向墙面主要在上午受光；但本次测试时刻是 09:25，峰值已经过去，并且当天中雨、高云量导致辐照折减很强。

## 6. 环境温度曲线

模型使用下面的日周期曲线近似环境温度：

```text
Tair(hour) = tmean + tempAmplitude * cos(2π * (hour - tempPeakHour) / 24)
```

代入本案例：

```text
Tair(hour) = 28 + 3 * cos(2π * (hour - 17) / 24)
```

解释：这条曲线表示当天环境温度以 28 ℃ 为均值，在 17:00 达到峰值，峰值附近约 31 ℃。

## 7. 空鼓温差模型

HTML 中的核心热响应模型保留下来，使用当前瓷砖饰面外墙 COMSOL 标定参数。

### 7.1 几何修正

```text
geometry = a / (a + ellA) * dk / (dk + d0)
```

其中：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `a` | 7.5 cm | 最小空鼓边长 |
| `dk` | 6 mm | 脱空厚度 |
| `ellA` | 27.4718 | 标定参数 |
| `d0` | 2.2169 | 标定参数 |

含义：空鼓尺寸越大、脱空厚度越大，热异常越容易形成。

### 7.2 热响应时间常数

```text
tauVoid = cVoid / (h + uVoid)
tauRef  = cRef  / (h + uRef)
```

含义：空鼓区和正常参考区的热响应速度不同。模型用低通滤波模拟这种“热惯性”差异。

### 7.3 局部温差

模型对墙面辐照 `Gwall` 和环境温度变化分别做低通滤波，再计算：

```text
ΔTlocal = Tvoid - Tref
```

结果含义：

- `ΔTlocal > 0`：空鼓区比参考区更热，形成正温差异常。
- `ΔTlocal < 0`：空鼓区比参考区更冷，形成负温差异常。

本案例计算得到：

```text
最大正温差 = +0.41 ℃
最小负温差 = -0.17 ℃
```

## 8. 窗口判断

系统只判断目标日期内的窗口。本案例目标日期是今天，测试时刻是 09:25，所以只检查 09:25 之后。

判断规则：

| 窗口类型 | 条件 |
| --- | --- |
| 正温差窗口 | `ΔTlocal >= +1.2 ℃` |
| 负温差窗口 | `ΔTlocal <= -1.2 ℃` |
| 有效持续时间 | 连续满足至少 1 小时 |
| 可用窗口 | `|ΔTlocal| >= 0.8 ℃` 连续至少 30 分钟 |

本案例：

| 指标 | 结果 | 是否达标 |
| --- | --- | --- |
| 最大正温差 | +0.41 ℃ | 未达到 +1.2 ℃ |
| 最小负温差 | -0.17 ℃ | 未达到 -1.2 ℃ |
| 正温差窗口 | 无 | 不达标 |
| 负温差窗口 | 无 | 不达标 |

最终推荐：

```text
当前条件不推荐检测
```

原因：

1. 东向墙面有效辐照峰值出现在 08:50，测试时刻 09:25 后已错过主要受热阶段。
2. 当天中雨、大雨预报，云量约 80%，降水合计较高，辐照折减到 0.25。
3. 计算得到的正负温差绝对值都明显低于 1.2 ℃阈值。

## 9. 单日计算边界

日期选择器是单选一天，因此推荐算法不做多天排序，也不输出多天范围。当前流程是：

1. 用户选择一个日期。
2. 系统选择能覆盖这个日期的最小天气预报跨度。
3. 从天气响应里只过滤目标日期的数据。
4. 只计算目标日期内的 00:00-24:00 曲线。
5. 如果目标日期是今天，只推荐当前时刻之后的窗口。

天气数据使用策略：

| 情况 | 使用方式 |
| --- | --- |
| 目标日逐小时温度点数充足 | 用逐小时温度计算 `tmean`、`tempAmplitude`、`tempPeakHour` |
| 目标日逐小时温度点数不足 | 用逐日最高/最低温估算 `tmean` 和 `tempAmplitude`，用可用逐小时最高温估算 `tempPeakHour` |
| 目标日期超过未来 30 天 | 当前和风逐日预报不覆盖，暂不计算 |

## 10. 本案例结论

本次真实案例的结果是“不推荐检测”。它不是算法失败，而是天气条件确实不利于红外空鼓检测：

- 降雨明显；
- 云量很高；
- 东向墙面有效辐照峰值已经过去；
- 模型预测温差没有达到检测阈值。

因此系统应提示用户改选天气更稳定、云量更低、辐照更强的日期，或选择更适合对应朝向的时段重新计算。
