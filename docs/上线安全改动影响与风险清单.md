# 上线安全改动影响与风险清单

更新时间：2026-07-13（Asia/Shanghai）

2026-07-13 策略调整：取消 IP 限流，只按用户/用户名限流；取消每日上传 100MB 限制；不再超过 1200 万像素就缩小；每任务 Qwen 并发仍为 5，全站同时任务数从 2 调整为 4。

## 1. 文档范围

本文记录 2026-07-11 至 2026-07-12 围绕“仅开放 Trial 和检测时段推荐、限制恶意调用”实施的改动，以及这些改动可能带来的兼容性、可用性和运维影响。

## 2. 关于高德旧 Key

旧 Key 在技术上可以继续使用，前提是高德控制台中仍处于启用状态。更换新 Key 是安全建议，不是程序运行的硬性要求。

建议更换的原因：

- 旧 `VITE_AMAP_KEY` 和 `securityJsCode` 曾经直接写在前端源码中。
- 浏览器端代码、Git 历史或曾经构建过的静态资源可能保留过这些值。
- Web Key 本身本来就会发送给浏览器，但 `securityJsCode` 不应该再被当作秘密使用。

如果决定继续使用旧凭据，正确做法是：

1. `VITE_AMAP_KEY` 放入根目录 `.env`，允许进入前端构建产物。
2. `AMAP_SECURITY_JS_CODE` 放入根目录 `.env`，禁止添加 `VITE_` 前缀。
3. Nginx 配置 `/_AMapService` 代理，在服务端追加 `jscode`。
4. 重新构建前端并重新加载 Nginx。

不要把 `securityJsCode` 再硬编码回 `ProjectLocationMap.tsx`。

## 4. 本轮主要改动与影响

### 4.1 Redis 限流、配额和会话撤销

相关文件：

- `backend/app/services/usage_control.py`
- `backend/app/api/auth.py`
- `backend/app/api/dependencies.py`
- `backend/app/core/config.py`

改动：

- 登录按用户名限流。
- 试用申请按申请用户名限流。
- Trial 生成按用户和每天模型 API 请求数限流。
- 天气请求按用户和每天上游调用量限流。
- 同一用户只能同时运行一个 Trial。
- 全站默认同时运行 4 个 Trial 任务；每个任务内部任一时刻最多并发 5 个 Qwen 请求，因此全站理论最大 Qwen 并发为 20。这里的 5 是并发数，不是一个任务的总请求数。
- Token 撤销记录由单进程内存改为 Redis，多 Uvicorn worker 共享。
- 生产环境 Redis 故障时采用 fail-closed：安全配额服务不可用会拒绝请求。

可能影响：

- Redis 短时故障会让登录、Trial、天气或 Token 校验返回 503，而不是继续放行。
- 登录限制统计同一用户名的成功和失败尝试；短时间重复登录可能收到 429。
- 取消 IP 限流后，攻击者可以通过批量用户名绕过登录/申请的单身份限额；这是按用户限流策略的固有取舍。
- 修改限额后，Redis 中旧计数会保留到当前 TTL 到期。
- 健康检查目前只报告 Redis“已配置”，没有实际 Ping Redis，因此 `/api/health=200` 不代表所有依赖都可用。

### 4.2 Trial 每日 API 额度和上传限制

相关文件：

- `backend/app/api/reports.py`
- `frontend/src/pages/TrialExperiencePage.tsx`

当前规则：

- 不限制每个用户每天成功上传或检测的照片总数。
- 默认每个用户按北京时间每天最多使用 800 次模型 API 请求，按推理切片数预占额度；管理员可在推理设置中调整。
- 模型调用失败时退回 API 请求额度；成功时按实际请求数退回多预占部分。
- 单张最大 10MB。
- 默认每个用户 10 分钟内最多上传 30 张照片、发起 5 次检测；管理员可在推理设置中调整检测次数，上传上限与限流窗口仍由后端环境配置维护。
- 不设置每日上传总 MB 限额。
- 未归档照片长期保留，不再自动清理。

可能影响：

- 单任务最多 10 张、单张最大 10MB；上传接口不按每日张数或累计 MB 拒绝。
- 失败上传如果已经成功写入 MinIO、但数据库提交异常，可能形成孤立对象；当前没有后台清理任务。
- 长期保留未归档照片会持续增加 MinIO 占用，需要容量监控、备份和用户用途说明。
- 若未来用于 YOLO 训练，应另行确认试用协议、隐私告知、数据授权和退出机制。

### 4.3 高分辨率照片和 Qwen 切片

相关文件：

- `backend/app/services/trial_qwen_inference.py`
- `backend/app/api/reports.py`

当前规则：

- 原始文件完整保存。
- 解码硬上限为 6400 万像素，用于拦截压缩图片炸弹。
- 6400 万像素解码安全上限内使用原始分辨率，不再以 1200 万像素作为缩小阈值。
- 单图最多 100 个切片。
- 整批最多 1000 个切片，以允许 10 张高分辨率图片一次提交。
- 支持 JPEG、PNG 和 DJI 常见 MPO；MPO 使用主画面推理。

可能影响：

- 原始分辨率有利于保留细小缺陷，但会显著增加切片数、Qwen 调用量、任务时延和费用。
- MPO 只使用第一帧；如果第二帧包含业务需要的热成像或其他信息，目前不会参与推理。
- 10 张高分辨率照片最多可产生约 1000 次 Qwen 调用，费用和延迟明显高于“10 张照片=10 次 API”。每任务同时只发 5 个，但总次数不会被 5 限制。
- 当前 Nginx 线上配置没有显式 `proxy_read_timeout`，默认超时可能不足以覆盖最慢的 10 张任务。代码版 `start-production.sh` 计划设置为 300 秒，但该 Nginx 配置尚未应用。
- 浏览器或 Nginx 超时不一定会取消后端正在执行的 Qwen 请求，可能出现用户看到失败但模型费用已经产生的情况。

### 4.4 Trial 归档行为

相关文件：`backend/app/api/reports.py`

改动：

- `/api/trial/results` 不再接受直接 multipart 文件，只接受已上传照片的 ID 和 JSON 结果。
- 已归档照片不能再次用于新的 Trial 生成或再次归档。
- Trial 结果归档不限份数。

可能影响：

- 旧客户端如果仍直接向 `/trial/results` 上传文件，会收到 415。
- 用户想对同一张已归档照片重新检测时，需要重新上传。
- 前端当前走“先上传，再 JSON 归档”流程，不受 multipart 变更影响。

### 4.5 MinIO 和基础设施端口

相关文件：

- `docker-compose.yml`
- `.env`
- `backend/app/services/object_storage.py`

改动：

- PostgreSQL、Redis、MinIO、算法模型端口从所有网卡收紧到 `127.0.0.1`。
- 后端 MinIO 地址改为 `localhost:9002`。
- 浏览器通过 `/api/object-storage/...` 签名 URL 读取图片，不直接访问 MinIO。

已发生回归：

- 第一次收紧端口后，`.env` 仍连接 `172.17.39.106:9002`，造成 Trial 上传失败和历史照片不可见。
- 已修正为 `MINIO_ENDPOINT=localhost:9002`，上传和历史 JPEG 读取已实测恢复。

可能影响：

- 局域网其他机器无法直接访问 PostgreSQL、Redis、MinIO 控制台或算法模型端口。
- 若未来部署独立服务器 Worker，不能继续用宿主机 LAN IP 直连这些端口，需要 Docker 内部网络、SSH 隧道或专门的安全入口。
- 运维人员从其他电脑访问 MinIO Console 会失败，这是预期的安全收紧。

### 4.6 检测时段推荐、天气和高德地图

相关文件：

- `frontend/src/router/index.tsx`
- `frontend/src/pages/CapabilityDetailPage.tsx`
- `frontend/src/components/project/ProjectLocationMap.tsx`
- `frontend/vite.config.ts`
- `backend/app/api/weather.py`
- `start-production.sh`

改动：

- `/capabilities/time` 改为要求登录。
- 天气接口仍要求登录。
- 天气坐标只接受 `经度,纬度`，不再接受任意 QWeather LocationID。
- 坐标统一保留两位小数作为缓存键。
- 天气增加 Redis 缓存、缓存击穿锁、用户限流和每日上游额度。
- 前端移除了明文 `securityJsCode`，改为 `window._AMapSecurityConfig.serviceHost`。
- 部署脚本增加高德 `/_AMapService` Nginx 代理，但线上 Nginx 尚未应用。

已发生回归：

- 受保护的静态路由错误复用了依赖 `:type` 参数的组件，导致点击后自动跳回首页。
- 已改为直接渲染 `TimeRecommendation`，Playwright 已验证页面和弹窗可打开。

当前实际影响：

- 页面现在可以打开，但因为高德 Key 和安全码仍是占位值，地图、地址搜索、坐标选择和最终查询按钮不可用。
- 未登录访问会跳回首页并打开登录弹窗，这是当前设计，不是路由错误。
- 如果希望检测时段页面公开访问，需要同时调整前端路由和后端天气鉴权/匿名配额，不能只移除前端登录保护。
- 即使把 Key 写入 `.env` 并重建前端，当前线上 Nginx 没有 `/_AMapService`，地图服务请求仍会失败；必须同步更新 Nginx。

### 4.7 账号和管理员密码

相关文件：

## 6. 仍可能出现的问题

### 高优先级

1. **检测时段功能目前仍不可真正查询**：页面可打开，但没有高德坐标，查询按钮无法启用。
2. **Nginx 线上配置未同步**：高德代理和长任务 300 秒超时都未上线。
3. **10 张 Qwen 任务的时延和费用未做完整端到端压测**：只做了批量预检、MPO 单测和单张/单 TILE 百炼烟测。
4. **浏览器断开不能保证取消后端 Qwen 请求**：可能产生“页面失败但费用已发生”。
5. **MinIO 无限保留需要容量管理**：目前没有清理、容量告警或训练数据授权字段。

### 中优先级

1. 不限制 IP 后，批量账号或批量申请更难阻断。
2. Redis 故障会使业务 fail-closed。
3. 已归档照片不能直接重跑。
4. 旧 multipart Trial 客户端不再兼容。
5. QWeather LocationID 调用不再兼容，只允许坐标。
6. 其他机器无法直连数据库、MinIO、Redis 和算法端口。
7. 当前健康检查没有真实检查 Redis、MinIO、QWeather 和百炼连通性。
8. 当前没有按用户记录精确百炼费用，只记录完成任务的照片数和切片数日志。
