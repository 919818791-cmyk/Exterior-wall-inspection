# /api/health 未授权信息泄露修复

原接口匿名返回运行环境、依赖配置状态、预检模型地址与名称、worker 后端地址、MinIO 地址、Token 配置状态及租约信息，并在探活时读取数据库中的策略。

修复后的行为：

| 请求 | 结果 |
| --- | --- |
| GET /api/health，不论是否登录 | 200，响应体严格为 `{"status":"ok"}`，Cache-Control: no-store |
| 匿名或无效 Token 请求 GET /api/health/details | 401，无诊断信息 |
| 普通用户、审核员请求 GET /api/health/details | 403，无诊断信息 |
| 有效管理员请求 GET /api/health/details | 返回原详细诊断，Cache-Control: private, no-store |
| 已注销、过期、被禁用或删除的管理员会话 | 拒绝详细诊断请求；管理员被降权后也立即拒绝 |

公开接口不再注入数据库连接、读取服务配置或查询模型服务；details/verbose 查询参数及伪造角色、回环 IP 请求头均不能扩大响应。响应模型将公开接口限制为单一 status 字段。公开的 ok 仅表示进程能够响应，不代表数据库、对象存储、Redis、worker 或模型已经就绪；需要详细状态的运维调用必须使用管理员诊断接口。已有 start.sh 探活调用不需要修改。

前端 HealthResponse 类型已同步为最小结构；预检策略回归测试改用管理员详细诊断路径，仍验证读取的是当前选中的模型配置。

本次 90 项测试通过，覆盖最小响应、匿名探活不读取依赖、参数及请求头无法绕过权限、管理员与其他角色、注销/过期/账号失效/降权、模型降级以及已有策略和认证行为。frontend 下 `npx tsc --noEmit -p tsconfig.json` 通过；本次前端只修改 TypeScript 类型，不改变运行时代码。

## 上线与复测

当前账号不能免密 sudo，尚未重启生产服务，不能判定线上漏洞已消除。管理员执行：

```bash
sudo systemctl restart building-exterior-backend.service
curl --noproxy '*' -i http://127.0.0.1:8000/api/health
curl --noproxy '*' -i http://127.0.0.1:8000/api/health/details
```

前一个请求应仅返回 `{"status":"ok"}`，后一个应返回 401。再从对外域名复测同样行为，并分别使用普通用户及管理员会话检查 403 和管理员诊断响应；不要把 Token 写入共享命令记录或日志。如前置网关曾缓存旧健康响应，上线时清除该路径的缓存，并确保遵循新的 no-store 响应头。

本次无需修改 Nginx。上一项高德代理修复仍须另外执行其 Nginx 迁移与前端安全发布步骤，见 [高德代理安全修复](高德代理安全修复.md)。
