# 识别质量评估

本功能覆盖专业检测。审核员逐张确认人工标注，管理员在“识别质量”查看项目及全局统计；快速体验尚无人工复核闭环，不纳入统计。

## 使用流程

1. 在审核工作台检查每张照片，调整框、类别，补充漏检和删除误检。
2. 点击“保存并确认本图”。没有缺陷也需要确认；仅“保存标注”或导入 JSON 仍为待复核。
3. 对模糊或无法判断的照片填写原因，点击“标记无法评估”。排除照片数量、原因保留展示。
4. 在报告预览中完成审核。所有送检照片均已复核或明确排除、且至少有一张可评估时，自动生成正式评估版本。
5. 管理员在 `/recognition-quality` 查看全局指标、类别统计、项目排序、历史版本及照片比对，导出 CSV。

未完成逐图复核时，项目详情仅展示已复核样本的阶段性结果，不计入全局正式评分。报告仍可按既有流程交付；完成报告审核并不自动证明照片已经复核。

## 规则

规则版本：`bbox-iou50-f1-v1`。

- 基线来自独立保存的 `ai_detection_result`，即切片合并、去重后的原图识别框。首次明确复核时冻结为 `quality_baseline`，不使用修改后的报告反推原始结果。
- 仅比较同一送检照片、同一检测类别。评估范围沿用任务的检测项记录。
- IoU ≥ 0.5 才能匹配。使用最大匹配数量优先、总 IoU 次优的一对一匹配，处理重复框和多框竞争，不依赖标注 ID 的相同与否。
- 匹配成功为 TP，未匹配 AI 框为 FP，未匹配人工框为 FN。类别错误或定位偏差过大，可以同时产生 FP 和 FN。
- 准确率（Precision）= TP / (TP + FP)；召回率 = TP / (TP + FN)；评分 = 200TP / (2TP + FP + FN)。界面准确率及召回率显示百分比，评分满分 100。
- 平均 IoU 仅统计正确匹配的框。置信度不作为实际准确率。
- 双方都没有框时，对象级指标为“—”，单列无缺陷照片判对情况；仅一方有框时评分为 0。分母为零的单项指标显示“—”。
- 复核覆盖率 = 已复核照片 / (送检照片 - 排除照片)。同时展示原始照片总数和排除数量，全部排除时不给评分。
- 项目及全局指标先汇总 TP、FP、FN，再计算，不能直接平均项目或照片分数。

细长裂缝的分段方式应保持一致。后续如果调整 IoU 阈值或评分公式，需要增加规则版本，不能直接改写历史版本。

## 数据与版本

迁移 `0064_recognition_quality` 为标注草稿增加复核状态、排除原因、复核人和时间；历史草稿一律保留为待复核。新增两张表：

- `quality_baseline`：原始送检照片清单、AI 框、模型与策略/提示词快照，按任务唯一。
- `quality_evaluation`：正式评估的指标、逐框匹配、人工基准及复核记录，按项目递增版本。

每次保存标注、JSON 导入、重置标注或旧接口修改审核结果，都会递增报告的质量修订号，使旧正式评分退出全局统计。重新复核并完成审核后产生新版本；相同修订重复完成审核不会重复建版本。历史版本仍可查看和导出。

写操作锁定报告行，避免同时复核、完成审核时丢失修订或生成重复版本。原始框永不被人工标注覆盖。历史任务缺少原始送检清单、检测项或完整 AI 结果时显示无法评估，不补造分数。无效坐标不能确认，可说明原因后排除该照片。

质量查询与导出仅允许管理员；审核员可以确认或排除照片，客户无法访问质量接口。CSV 对用户输入做公式转义。历史照片预览地址在读取时重新签名，不保存过期链接。

## 接口

| 接口 | 用途 |
| --- | --- |
| `GET /api/recognition-quality` | 全局概览、分页项目列表，支持 search 和 sort（recent/score/missed） |
| `GET /api/recognition-quality/projects/{project_id}` | 当前正式评估或阶段性结果，`?version=N` 查看历史 |
| `GET /api/recognition-quality/export` | 项目汇总 CSV |
| `GET /api/recognition-quality/projects/{project_id}/export` | 逐框明细 CSV，可指定历史版本 |
| `PUT /api/review/detections/{task_id}/annotations/photos` | 原保存接口，新增 review_state 和 exclusion_reason |

`review_state` 为 pending、reviewed 或 excluded，默认为 pending；excluded 必须提供原因。

## 启用与验证

先在后端环境执行数据库迁移，再重启后端进程并构建前端：

```bash
cd backend
.venv/bin/alembic upgrade head
```

前端构建命令为 `npm run build`。本次验证在独立 PostgreSQL schema 内运行迁移的升级、回退及再次升级，不修改当前运行数据库；浏览器验证使用隔离的测试数据库。

后端测试覆盖一对一匹配、重复框、类别错误、定位错误、漏检、阈值边界、无框、汇总方式、排除原因、非有限坐标、明确复核与普通草稿的区别、版本幂等、旧分数失效及权限。浏览器检查桌面和手机布局、筛选、放大定位、历史、CSV 导出及照片确认。
