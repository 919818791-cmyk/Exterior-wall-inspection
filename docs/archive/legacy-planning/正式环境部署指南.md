# 正式环境部署指南

> **历史方案备注（2026-07-14）**：本文已归档。YOLO/Worker 部署与正式项目管理链路均已暂停；相关命令和配置不应纳入当前生产部署。

本文档用于在一台已安装 Linux 系统的正式环境服务器上部署外墙智能巡检平台。

推荐部署方式：

- Docker Compose 运行 PostgreSQL、MinIO、Redis。
- FastAPI 后端使用 Python venv + systemd 常驻运行。
- React 前端构建为静态文件后由 Nginx 提供访问。
- Nginx 负责把 `/api/` 反向代理到后端。

以下命令默认服务器系统为 Ubuntu 22.04 / 24.04。

## 1. 安装基础软件

```bash
sudo apt update
sudo apt install -y git curl ca-certificates gnupg nginx python3 python3-venv python3-pip
```

安装 Docker Engine 和 Docker Compose 插件后确认版本：

```bash
docker --version
docker compose version
```

Node.js 需要 20 或更高版本。安装完成后确认：

```bash
node -v
npm -v
```

## 2. 拉取项目代码

```bash
sudo mkdir -p /opt/building-exterior
sudo chown -R $USER:$USER /opt/building-exterior
git clone -b codex/deploy-runtime-package https://github.com/919818791-cmyk/Exterior-wall-inspection.git /opt/building-exterior
cd /opt/building-exterior
```

如果服务器已经拉过代码，后续更新时使用：

```bash
cd /opt/building-exterior
git pull
```

## 3. 配置正式环境变量

```bash
cd /opt/building-exterior
cp .env.example .env
nano .env
```

建议正式环境至少修改以下配置：

```env
APP_ENV=production
DEBUG=false
API_PREFIX=/api

VITE_API_BASE_URL=/api
VITE_AMAP_KEY=替换为新申请的高德Web端Key
VITE_AMAP_SERVICE_HOST=/_AMapService
AMAP_SECURITY_JS_CODE=替换为高德安全密钥
BACKEND_CORS_ORIGINS=http://服务器IP

POSTGRES_HOST=localhost
POSTGRES_PORT=5433
POSTGRES_DB=building_exterior
POSTGRES_USER=building_exterior
POSTGRES_PASSWORD=换成强密码
DATABASE_URL=postgresql+psycopg://building_exterior:你的强密码@localhost:5433/building_exterior

MINIO_API_PORT=9002
MINIO_CONSOLE_PORT=9003
MINIO_ENDPOINT=localhost:9002
MINIO_PUBLIC_URL=http://localhost:9002
MINIO_ACCESS_KEY=换成强账号
MINIO_SECRET_KEY=换成强密码
MINIO_BUCKET=building-exterior

REDIS_URL=redis://localhost:6379/0
TRIAL_DAILY_PHOTO_LIMIT=10
TRIAL_DAILY_UPLOAD_PHOTO_LIMIT=10
TRIAL_MAX_FILE_SIZE_BYTES=10485760
TRIAL_MAX_IMAGE_PIXELS=64000000
TRIAL_INFERENCE_MAX_IMAGE_PIXELS=64000000
TRIAL_MAX_TILES_PER_IMAGE=100
TRIAL_MAX_TILES_PER_REQUEST=1000
TRIAL_GLOBAL_JOB_CONCURRENCY=4

WORKER_BACKEND_BASE_URL=http://localhost:8000
WORKER_CONTAINER_BACKEND_BASE_URL=http://host.docker.internal
WORKER_ID=mock-worker-local
WORKER_TOKEN=换成强随机token
WORKER_MODEL_VERSION=mock-facade-detector-v1
WORKER_LEASE_SECONDS=600
WORKER_MODE=mock
ALGORITHM_INFERENCE_URL=http://algorithm-model:9002
ALGORITHM_INFERENCE_TIMEOUT_SECONDS=120

DASHSCOPE_API_KEY=替换为实际百炼API-Key

AUTH_ACCESS_TOKEN_EXPIRE_MINUTES=120
AUTH_SEED_DEMO_USERS=false
SECURITY_STORE_BACKEND=redis
SECURITY_FAIL_CLOSED=true
```

生成 `AUTH_SECRET_KEY`：

```bash
openssl rand -hex 32
```

注意：

- `VITE_API_BASE_URL=/api` 表示前端通过当前站点的 `/api` 访问后端，适合 Nginx 反向代理部署。
- 高德 Web Key 会出现在浏览器中；安全密钥只能配置为服务端的 `AMAP_SECURITY_JS_CODE`，由 Nginx `/_AMapService` 代理注入，禁止使用 `VITE_AMAP_SECURITY_JS_CODE`。
- `DASHSCOPE_API_KEY` 只供后端 `/trial` 使用，不要添加 `VITE_` 前缀，也不要提交到版本库。
- MinIO 仅供本机后端和 Worker 使用；浏览器通过带签名的 `/api/object-storage/...` 读取对象，不需要开放 MinIO 公网端口。
- `WORKER_BACKEND_BASE_URL` 用于本机直接运行 Worker；`WORKER_CONTAINER_BACKEND_BASE_URL` 用于 Docker Worker，默认通过宿主机 Nginx 访问 `/api`。
- 生产环境不得启用演示账号自动创建。部署脚本会执行 `python -m app.db.harden_production_accounts`，禁用固定 customer/reviewer 演示账号；该脚本不会修改管理员账号或管理员密码。

默认演示账号：

| 角色 | 用户名 | 密码 |
| --- | --- | --- |
| 客户用户 | `customer` | `Customer123!` |
| 内部审核人员 | `reviewer` | `Reviewer123!` |
| 管理员 | `admin` | `Admin123!` |

## 4. 启动数据库、对象存储和缓存

```bash
cd /opt/building-exterior
docker compose up -d postgres minio redis
docker compose ps
```

默认端口：

- PostgreSQL：`5433`
- MinIO API：`9002`
- MinIO Console：`9003`
- Redis：`6379`

这些端口通过 Docker Compose 默认只绑定 `127.0.0.1`，均不得开放到公网。

## 5. 初始化后端

```bash
cd /opt/building-exterior/backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
alembic upgrade head
python -m app.db.check_connection
```

本地验证后端能启动：

```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

另开一个终端验证：

```bash
curl http://127.0.0.1:8000/api/health
```

验证通过后按 `Ctrl+C` 停止临时进程。

## 6. 配置后端 systemd 服务

创建服务文件：

```bash
sudo nano /etc/systemd/system/building-exterior-backend.service
```

写入以下内容，把 `你的Linux用户名` 替换成实际用户：

```ini
[Unit]
Description=Building Exterior Backend
After=network.target docker.service

[Service]
User=你的Linux用户名
WorkingDirectory=/opt/building-exterior/backend
ExecStart=/opt/building-exterior/backend/.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 2
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

启动服务：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now building-exterior-backend
sudo systemctl status building-exterior-backend
curl http://127.0.0.1:8000/api/health
```

查看后端日志：

```bash
sudo journalctl -u building-exterior-backend -f
```

## 8. 配置 Nginx

创建站点配置：

```bash
sudo nano /etc/nginx/sites-available/building-exterior
```

写入以下内容，把 `服务器IP` 替换成实际 IP 或域名：

```nginx
server {
    listen 80;
    server_name 服务器IP;

    root /opt/building-exterior/frontend/dist;
    index index.html;
    client_max_body_size 105M;

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /_AMapService/v4/map/styles {
        set $args "$args&jscode=你的高德安全密钥";
        proxy_ssl_server_name on;
        proxy_set_header Host webapi.amap.com;
        proxy_pass https://webapi.amap.com/v4/map/styles;
    }

    location /_AMapService/ {
        set $args "$args&jscode=你的高德安全密钥";
        proxy_ssl_server_name on;
        proxy_set_header Host restapi.amap.com;
        proxy_pass https://restapi.amap.com/;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

启用站点：

```bash
sudo ln -s /etc/nginx/sites-available/building-exterior /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

访问：

```text
http://服务器IP
```

## 9. 防火墙建议

```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable
sudo ufw status
```

说明：

- `80` / `443` 用于访问系统页面和 API。
- MinIO `9002/9003`、PostgreSQL `5433` 和 Redis `6379` 均不得公网开放。

## 10. 首次上线检查

```bash
curl http://127.0.0.1:8000/api/health
sudo systemctl status building-exterior-backend
docker compose ps
```

浏览器检查：

1. 打开 `http://服务器IP`。
2. 使用自己的管理员账号登录；部署脚本不会创建或修改管理员密码。
3. 进入账号管理，修改默认密码或创建正式管理员。
4. 上传一张图片，确认图片预览、简易检测、结果归档可以正常使用。
5. 确认报告详情页的图片可以在其他电脑浏览器中正常打开。

完成账号初始化后，建议修改 `.env`：

```env
AUTH_SEED_DEMO_USERS=false
```

然后重启后端：

```bash
sudo systemctl restart building-exterior-backend
```

## 12. 算法 Worker 说明

简易检测体验直接调用百炼 `qwen3-vl-plus`，不依赖本地 `.pt` 权重或 `algorithm-model` 容器；但必须先配置后端专用的 `DASHSCOPE_API_KEY`。以下本地模型和 Worker 部署只用于正式项目检测任务。

如果要验证模拟 Worker：

```bash
cd /opt/building-exterior
docker compose --profile worker run --rm algorithm-worker
```

正式接入真实算法时，建议拆成两个服务：

- `algorithm-worker`：持有后端 Worker Token，主动领取任务、下载图片、调用模型并回传结果。
- `algorithm-model`：只提供内部推理接口，不直接访问数据库，不持有 Worker Token，不映射公网端口。

正式项目链路中 Web 后端不直接调用本地算法模型，Worker 也不放进 Web 后端进程。`/trial` 是独立链路，由 Web 后端直接调用百炼 API。

### 12.1 PyTorch / CUDA 模型容器

如果正式服务器使用 NVIDIA GPU，先在宿主机确认驱动和 Docker GPU 运行时可用：

```bash
nvidia-smi
docker run --rm --gpus all nvidia/cuda:12.9.0-base-ubuntu22.04 nvidia-smi
```

将算法同事提供的模型权重放到默认目录：

```bash
cd /opt/building-exterior
mkdir -p models
# 上传或复制权重到 models/model.pt
```

构建并验证模型运行环境：

```bash
docker compose --profile algorithm-gpu build algorithm-model
docker compose --profile algorithm-gpu run --rm algorithm-model python verify_environment.py
```

默认使用 `PYTORCH_INDEX_URL=https://download.pytorch.org/whl/cu128` 安装 PyTorch CUDA 12.8 wheel，并安装 `ultralytics-opencv-headless`，适合无头服务器和 Docker 容器。若算法侧确认使用其他 CUDA / PyTorch 版本，修改 `.env` 中的 `PYTORCH_INDEX_URL` 后重新构建镜像。

启动模型容器：

```bash
docker compose --profile algorithm-gpu up -d algorithm-model
docker compose --profile algorithm-gpu exec algorithm-model python verify_environment.py
```

`algorithm-model` 默认只在 Docker 内部网络暴露 `9002`，不映射公网端口。真实推理接口由算法侧在 `algorithm-model` 内实现，`algorithm-worker` 通过 `ALGORITHM_INFERENCE_URL=http://algorithm-model:9002` 调用。

## 13. 常见问题

### 前端提示无法连接后端

检查 `.env`：

```env
VITE_API_BASE_URL=/api
```

重新构建前端：

```bash
cd /opt/building-exterior/frontend
npm run build
sudo systemctl reload nginx
```

检查 Nginx 是否代理成功：

```bash
curl http://服务器IP/api/health
```

### 图片在服务器能看，其他电脑看不了

确认后端提供的 `/api/object-storage/...` URL 可访问，并检查本机 MinIO 配置：

```env
MINIO_ENDPOINT=localhost:9002
MINIO_PUBLIC_URL=http://localhost:9002
```

然后重启后端：

```bash
sudo systemctl restart building-exterior-backend
```

### 数据库迁移失败

检查数据库容器状态：

```bash
docker compose ps postgres
docker logs building-exterior-postgres --tail 100
```

检查连接：

```bash
cd /opt/building-exterior/backend
source .venv/bin/activate
python -m app.db.check_connection
```

### 后端服务无法启动

查看日志：

```bash
sudo journalctl -u building-exterior-backend -n 200 --no-pager
```

常见原因：

- `.env` 数据库密码和 Docker Compose 使用的密码不一致。
- `DATABASE_URL` 写错。
- Python 依赖未安装。
- Alembic 迁移未执行。

### Nginx 配置不生效

检查配置并重载：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

如果默认站点占用了请求，可以禁用默认站点：

```bash
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
```

## 14. HTTPS 建议

如果有域名，建议使用 HTTPS：

- 前端/API 通过 `https://你的域名` 访问。
- `.env` 中 `BACKEND_CORS_ORIGINS` 改成 `https://你的域名`。
- `MINIO_ENDPOINT` 和 `MINIO_PUBLIC_URL` 也应使用浏览器可访问的 HTTPS 地址。

生产环境不要长期使用默认密码、默认 Worker Token 或默认管理员密码。
