# 高德地图代理安全修复

代码与部署配置必须一起上线。仅修改前端，或收到 `USER_KEY_RECYCLED (10013)`，都不能判定整改完成。

## 改动

- 登录后以 Bearer 请求 `POST /api/maps/session`，签发最长 30 分钟、且不超过原登录期限的随机地图票据。Cookie 为 HttpOnly、SameSite=Strict、Path=/_AMapService，生产与预发布加 Secure；前端每 20 分钟续期。
- 每次代理请求都从服务端票据记录恢复登录身份，校验 Token 有效期、注销撤销记录、账号启用及删除状态。缺失、伪造、过期票据返回 401；安全存储故障拒绝服务。地图票据不能用于其他业务接口。
- 仅开放实际使用的 `v3/geocode/geo`、`v3/geocode/regeo`、`v3/place/text`。未知路径 404，重复及非白名单参数、安全码覆盖、JSONP 注入和批量查询 400；每账号每分钟默认 60 次，超限 429。样式与 SDK 日志接口不转发上游。
- 固定 HTTPS 高德上游，不转发客户端认证头或 Cookie，不跟随重定向，不接收任意目标地址；超时 10 秒，响应上限 2 MiB。只注入服务端配置的 Key、安全码。
- 上游须返回成功 JSON 对象，异常统一返回 502；递归删除 key、apiKey、jscode、securityJsCode、sec_code、sec_code_debug 等字段，字符串中的实际凭据也会替换。JSONP 过滤后重建，不直接转发上游脚本。
- 成功与失败均禁止缓存，移除所有 Access-Control-* 授权头，设置 nosniff 及同源资源策略。跨站、不同 Origin、OPTIONS 返回 403；Origin 检查不能替代登录鉴权。
- Vite 开发与预览统一走后端。Nginx 迁移脚本移除全部旧高德直通规则，代理入口不记录包含查询字符串的访问日志。

高德 Web JS Key 是浏览器 SDK 使用的公开标识：移除构建时 `VITE_AMAP_KEY` 能消除静态 JS 内嵌 Key，但登录用户仍能在 SDK 网络请求中看到运行时 Web Key。安全码始终只存服务端。若验收要求浏览器完全无法获得任何 Key，需要替换 JS SDK 接入方式，动态加载不能满足这一要求。

## 配置与上线

本机 `.env` 内 `VITE_AMAP_KEY` 已迁移为 `AMAP_JS_API_KEY`，未打印凭据。其他部署环境需同步迁移。删除旧的 VITE_AMAP_KEY、VITE_AMAP_SERVICE_HOST、VITE_AMAP_SDK_URL、AMAP_WEB_API_URL、AMAP_REST_API_URL 配置，使用：

```dotenv
AMAP_JS_API_KEY=<Web端JSAPI Key>
AMAP_SECURITY_JS_CODE=<对应安全密钥>
AMAP_RATE_LIMIT_PER_USER=60
```

在高德控制台更换已暴露或已删除的凭据，设置真实业务域名白名单，不要复用 Web 服务 Key。10013 官方含义为 Key 被删除，需要配置可用的配套凭据；更换凭据后仍须复测访问控制。

验证代码：

```bash
cd /opt/Exterior-wall-inspection/backend
.venv/bin/python -m pytest tests/test_amap_security.py tests/test_phase8_auth.py tests/test_config.py -q
```

生产执行顺序（需要管理员 sudo 权限；当前会话无法免密 sudo，尚未执行）：

```bash
cd /opt/Exterior-wall-inspection
sudo systemctl restart building-exterior-backend.service
curl --noproxy '*' -fsS http://127.0.0.1:8000/api/health
sudo python3 deploy/configure-nginx-amap.py
cd frontend
RETIRE_OLD_JS_ASSETS=1 npm run build
```

迁移脚本将高德路径及会话初始化路径指向原 `/api/` 相同后端，备份后检查 `nginx -t` 并重载；失败自动恢复。备份含历史安全码，权限为 0600，后续应按凭据管理要求清理。若 API 使用非默认前缀，需同步调整 Nginx 会话路径。

`RETIRE_OLD_JS_ASSETS=1` 在发布新入口后移除旧 JS 与 sourcemap，避免旧 bundle 继续暴露历史 Key；部分旧标签页需刷新。普通构建仍保留历史资源。如前置 CDN 缓存旧 JS，发布时清除缓存。不要先发布新前端而保留旧后端。

Uvicorn 的完整请求行可能记录 SDK 传入的公开 Web Key，应限制日志访问及保留期，或使用 `--no-access-log`。服务端附加的安全码不会出现在入站请求中。

## 复测

自动测试使用假数据库、真实 Token 签名及撤销逻辑和受控上游响应，不修改业务数据，不调用真实高德。上线后还需：

1. 匿名访问 /_AMapService/v3/geocode/geo 及 POST /api/maps/session 均返回 401，不能得到高德原始响应。
2. 登录后的未知接口 404，覆盖 jscode、重复参数和 callback 注入 400，跨站请求 403，所有地图响应均无 Access-Control-Allow-Origin: *。
3. 浏览器登录后验证地图、正逆地理编码、地点搜索；注销或禁用账号后复用地图 Cookie 应返回 401。
4. 新 JS 不含实际凭据；旧 bundle URL 不再返回旧脚本；上游错误、嵌套结构均无 key/sec_code/sec_code_debug 等敏感字段。
5. 上游 10013 只能得到统一错误。地图正常功能需配置可用 Key 后验证，不能用错误响应代替成功业务验收。

官方依据：[安全密钥使用](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)、[错误码说明](https://developer.amap.com/api/javascript-api-v2/guide/abc/errorcode)。

本次本地验证：上述后端测试 65 项通过；TypeScript 检查与隔离目录生产构建通过，53 个构建 JS 未检出当前配置的 Key 或安全码。临时浏览器测试挂载真实 ProjectLocationMap 组件，经 Vite 和后端校验 HttpOnly Cookie、JSONP 地理编码、字段过滤、匿名 401 与未知接口 404；SDK 和高德上游使用受控替身，不能视为真实高德可用性验收。构建发布脚本另在临时目录验证普通构建保留旧脚本、安全发布删除旧脚本，未改动正在提供服务的 dist。生产 Nginx 迁移与服务重启尚未执行。
