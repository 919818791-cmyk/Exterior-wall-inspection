# 项目与报告接口强制鉴权及对象隔离

## 原因与修复范围

项目、报告及部分项目子资源的只读接口原先使用可选登录依赖，允许匿名查询共享示例；非示例详情也会先查询数据库，再返回 404。下载、写入接口已经强制登录，导致策略不一致。

本次将项目、报告、项目照片及建筑模型路由统一声明 `Depends(get_current_user)`，对应只读处理函数也改为要求 `AuthenticatedUser`，删除未使用的可选登录依赖及匿名筛选分支。认证失败时在业务查询前返回 401，并附带 `WWW-Authenticate: Bearer`。项目对象授权函数也拒绝匿名访问示例。

受保护的只读接口包括：

- `GET /api/projects`
- `GET /api/projects/{project_id}`
- `GET /api/projects/{project_id}/photos`
- `GET /api/projects/{project_id}/building-model`
- `GET /api/projects/{project_id}/building-model-images`
- `GET /api/projects/{project_id}/reviewed-result`
- `GET /api/reports`
- `GET /api/reports/{report_id}`
- `GET /api/reports/{report_id}/docx`
- `GET /api/reports/{report_id}/pdf`

检测配置接口原有的强制登录要求继续有效。

## 访问规则

| 场景 | 结果 |
| --- | --- |
| 匿名、非 Bearer、无效或过期凭证访问上述接口 | 401，不查询业务对象 |
| 匿名访问不存在或格式错误的对象 ID | 401，优先执行鉴权 |
| 客户查看列表 | 仅返回本人和共享示例数据 |
| 客户读取本人或共享示例的项目、照片、模型、已审核结果、报告 | 按原业务状态规则提供访问 |
| 客户读取其他账号的非示例项目、报告，或下载报告 | 404，隐藏对象是否存在 |
| 客户重命名、删除、恢复其他账号的体验报告 | 404 |
| 已登录用户修改共享示例 | 保留只读限制 |
| 审核员、管理员 | 保留现有角色权限；审核员的体验记录仍仅限本人及示例 |

`include_generated=true` 不绕过认证或归属筛选。认证继续复用既有的有效账号、会话撤销及 Token 校验。

前端将专业检测、体验记录列表与结果详情、建筑模型页面移入现有 `RequireAuth` 守卫，匿名访问跳转登录并保留目标地址，避免页面直接请求受保护接口后仅显示加载失败。首页及法律文件保持公开访问。旧 `/projects`、`/reports` 入口跳转后也进入登录守卫。

## 验证结果

```bash
cd backend
.venv/bin/python -m pytest tests/test_project_report_authorization.py tests/test_phase8_auth.py -q
```

120 项通过。其中新增 87 项，覆盖 15 个 URL 的四类无效认证、认证失败前不查询数据库，以及 SQLite 测试数据上的本人／他人／示例对象隔离、报告下载与修改权限。已有授权测试同步移除匿名可读的旧预期。

全量后端测试为 933 通过、6 跳过、7 失败。7 项均在隔离副本中撤销本次鉴权修改后复现相同断言失败：

- `test_phase3_project_routes_are_registered`：旧断言禁止任意路径包含 `facade`，与已有配置路由冲突。
- `test_inference_and_estimation_use_identical_validated_limits`：现有分批推理增加了一次估算调用。
- `test_phase7_routes.py` 中 5 个体验推理测试：检测结果为空，与原断言不符。

前端 `tsc --noEmit -p tsconfig.json` 通过；Playwright 在本地 Vite 实例验证 7 个业务及旧入口均跳转登录、保留正确目标地址，3 个公开页面正常访问，期间没有匿名项目或报告 API 请求。

当前修改已完成源码与本地测试，尚未重启运行中的后端或发布新前端。当前账号执行免密 sudo 返回需要密码；修复后对运行服务的匿名实测仍为旧的 200，不能据此认定线上漏洞已消除。

```bash

sudo systemctl restart building-exterior-backend.service
```

