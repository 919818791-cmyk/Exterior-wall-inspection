# 普通用户功能容错审计

审计日期：2026-07-24

## 审计范围

- 注册
- 登录
- 修改账号信息与密码
- 检测时段推荐
- 智能检测（TRIAL）
- 检测结果列表与详情

审计重点是误操作、不可逆操作、重复提交、状态丢失、失败恢复、会话过期和结果误读。

## 总体判断

系统已经具备基础输入校验、提交中禁用、上传进度、单图重试、天气逐小时数据失败后降级、报告删除确认等机制，但仍有四个高风险缺口：

1. 普通用户可以删除已推送的正式检测结果，后端会同时删除报告文件和数据库记录。
2. TRIAL 中删除已上传照片、带未保存名称退出、取消返回都没有确认或恢复入口。
3. TRIAL 检测请求缺少任务 ID、状态恢复和幂等键，网络超时后的重试可能造成重复检测、重复扣额或重复归档。
4. 检测时段推荐中，用户修改地址但不执行“搜索定位”时，旧坐标仍然有效并可直接查询，结果可能针对错误位置。

## 分步骤检查

### Step 1：登录 — 一般

现状：

- 必填字段和提交中禁用已具备。
- 后端合并提示“用户名、手机号或密码错误”，不会泄露账号是否存在。
- “忘记密码”按钮没有实际流程。
- 会话过期没有全局统一处理；业务接口返回 401 后，页头仍可能保持已登录外观。

建议：

- 不增加登录确认弹窗。
- 增加密码显隐、Caps Lock 提示、限流剩余时间和可用的找回密码流程。
- 在 API 层统一处理 401：清理会话、保存当前路由和未完成草稿、重新登录后返回。

证据：[01-login.png](screenshots/01-login.png)

### Step 2：注册 — 较差

复现：

- 表单填写后点击关闭，未出现离开确认。
- 再次打开注册表单，全部内容已清空。
- 没有确认密码字段和手机验证码。

建议：

- 表单发生变更后，关闭、按 Escape 或切换页面时提示“继续填写 / 放弃内容”。
- 增加确认密码、密码显隐和逐字段错误。
- 手机号用于登录且要求唯一，应先完成短信验证码验证；这比提交前再弹一次“是否确认注册”更有效。
- 注册请求增加幂等键；后端应先完成格式校验，再消耗频率额度。

证据：[02-register-unsaved.png](screenshots/02-register-unsaved.png)

### Step 3：个人资料与密码 — 较差

复现：

- 姓名和单位修改后直接关闭，没有确认，重新打开后编辑内容丢失。
- 修改密码成功后会注销当前会话，但弹窗中没有提前告知。

建议：

- 资料变更后关闭、按 Escape、点遮罩或“取消”时提示是否放弃；保存成功后给出明确成功反馈。
- 普通姓名和单位保存不需要每次确认，可用自动保存或保存后撤销降低干扰。
- 修改密码按钮附近明确说明“修改成功后需要重新登录”；成功后先显示结果，再跳转登录。
- 如果未来允许修改手机号，必须验证旧手机号或当前密码，并验证新手机号。

证据：[03-account-unsaved-edit.png](screenshots/03-account-unsaved-edit.png)、[04-change-password.png](screenshots/04-change-password.png)

### Step 4：检测时段推荐 — 一般

复现：

- 地图选中一个坐标后，把地址改成另一个尚未搜索的新地址，“查询推荐”仍可点击。
- 逐小时天气失败时会退回逐日数据计算，这是已有优点。
- 日期控件没有直接限制未来 30 天，错误只在提交后出现。
- 查询过程中关闭弹窗不需要确认，也没有可恢复的查询记录。

建议：

- 地址文本变化后，将坐标标记为“待重新定位”，直到用户搜索或再次点选地图。
- 日期控件设置最小、最大日期，避免提交后才报错。
- 正在查询时关闭应提供“后台继续 / 取消查询 / 留在页面”；如果查询消耗日额度，提交前展示本次消耗说明。
- 结果中展示天气更新时间、数据来源和“仅供采集计划参考，不替代现场安全判断”。

证据：[05-time-recommendation-input.png](screenshots/05-time-recommendation-input.png)、[06-time-recommendation-fallback.png](screenshots/06-time-recommendation-fallback.png)

### Step 5：TRIAL 上传与生成 — 较差

已有优点：

- 文件格式、大小和数量校验。
- 上传进度、单图失败提示和单图重试。
- 上传、生成、归档期间会禁用部分按钮。

复现：

- 删除一张已上传但未归档的照片时，删除请求立即发送，没有确认或撤销。
- 生成后修改报告名称但不保存，点击“完成并退出”不会提示，也不会保存名称。
- 生成前点击“取消并返回”以及从顶部导航离开，没有未完成内容保护。

建议：

- 对已上传照片使用“删除后 5 秒可撤销”，无法撤销时再使用确认弹窗；按钮要有单图删除中状态。
- 页面离开保护应覆盖顶部导航、取消返回、退出登录、浏览器刷新和关闭标签页。
- “完成并退出”应先等待名称保存完成；保存失败时留在页面。
- 检测改为服务端任务：提交后返回任务 ID，页面通过查询恢复进度和结果。
- 上传、生成、追加归档都增加幂等键；网络超时后先查任务状态，再允许重试。
- 多照片任务支持部分成功，明确显示失败照片并只重试失败项。
- 对大批量或“再次检测/追加到已有结果”显示照片数、检测类型和预计额度消耗确认；小批量首次检测无需额外确认。
- 取消后清理未归档对象，或设置自动过期回收。

证据：[07-trial-empty.png](screenshots/07-trial-empty.png)、[08-trial-uploaded.png](screenshots/08-trial-uploaded.png)、[09-trial-result.png](screenshots/09-trial-result.png)

### Step 6：检测结果列表与详情 — 高风险

复现：

- 正式结果和 TRIAL 结果都显示相同的“删除”按钮。
- 已推送正式结果会弹出确认，但文案只说“从检测结果列表移除”。
- 后端实际会删除正式报告文件和数据库记录，并清空项目当前报告关联；这不是“从列表移除”。
- 详情页只显示“疑似裂缝：1处”，普通用户看不到单图处理是否完整、置信度或 AI 结果限制。
- 正式 DOCX 下载失败没有页面错误反馈；列表和详情加载失败也缺少就地重试。

建议：

- P0：普通用户禁止删除已推送正式报告；如业务必须允许，只能进入回收站并支持恢复，不能直接物理删除。
- TRIAL 结果使用自定义确认框，明确“照片、标注和导出记录都会删除”，并提供回收站或撤销。
- 删除成功后给出结果和恢复入口；失败时保留目标行并显示具体原因。
- 详情页显示每张照片的处理状态、失败/跳过原因、检测覆盖率和“AI 结果需人工复核”。
- 区分“检测成功但未发现缺陷”和“照片未完成检测”，避免给出错误的安全感。
- 为列表加载、详情加载、图片加载和 DOCX/PDF 导出增加就地重试。

证据：[10-results-list.png](screenshots/10-results-list.png)、[11-result-detail.png](screenshots/11-result-detail.png)

## 优先级

### P0

1. 禁止普通用户物理删除已推送正式报告。
2. TRIAL 增加任务 ID、幂等键、状态恢复和离开页面保护。
3. 修复地址文本与地图坐标可能不一致的问题。

### P1

1. 注册和个人资料的未保存内容保护。
2. 手机号验证、确认密码、找回密码。
3. TRIAL 照片删除撤销、脏报告名称自动保存。
4. 结果页的处理完整性、失败项和 AI 复核提示。
5. 全局 401 会话恢复。

### P2

1. 日期前置限制、限流倒计时、天气数据更新时间。
2. 下载和加载的就地重试。
3. 密码显隐、Caps Lock 和保存成功提示。

## 证据限制

- 登录后的用户、天气响应、TRIAL 响应和结果数据使用浏览器本地拦截的代表性数据，未消耗真实天气/模型额度，也未写入正式检测结果。
- 登录前页面、地图交互和所有前端关闭、删除、退出行为使用当前代码实际运行。
- 截图不能确认完整键盘操作、焦点陷阱、屏幕阅读器播报或 WCAG 合规；这些需要专项可访问性测试。
